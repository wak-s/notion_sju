# 인수인계: 신청자 어드민 목록 화면 (CX 요구사항, 2026-10-09)

어드민을 만들 대화창에 이 문서를 그대로 붙여넣으면 됩니다.
백엔드·DB 구조는 `docs/HANDOFF-supabase.md`, 화면에서 CL이 해야 할 일은 이 문서가 기준입니다.

## 목적 한 줄
CL(곽시우)이 신청이 들어온 걸 바로 알아보고, 결과에 맞게 연락·지원하고, 처리 상태를 남기는 화면.
노션 [DB] CX.zip 대신 쓰는 곳이라 "노션 DB에서 하던 일"이 그대로 돼야 한다.

## 접근
- 주소 예: `/admin` (검색 노출 막기: `noindex`)
- **CL만 볼 수 있어야 함.** 신청자 이름·전화번호가 보이는 화면이라 로그인 없이 열리면 안 됨
- 브라우저에 DB 키를 두지 않는 지금 원칙 유지 → 서버 API(`/api/admin/...`)를 통해서만 읽기·쓰기

## 목록에 보일 칸 (왼쪽부터 중요한 순)
| 칸 | DB | 비고 |
|---|---|---|
| 신청일시 | created_at / updated_at | 재신청이면 "재신청 n회"(submit_count) 표시 |
| 이름 · 전화번호 | name, phone | 전화번호 누르면 바로 전화·문자 |
| 결과 | result_code + result_name | 예: `P1 학기 사령탑` |
| 트랙 | track | 개인 학생 / 동아리 대표 / 운영진·멤버 |
| 지원 수준 | want_setup, level, usage, role | 아래 "대응 규칙"대로 한 줄 요약해 보여주면 좋음 |
| 들어온 경로 | utm_source / utm_medium / utm_campaign | 없으면 referrer_host |
| 소식 받기 동의 | consent_marketing | 행사 홍보 문자는 이 칸이 참인 사람에게만 |
| **처리 상태** | **새 칸 필요** | 신규 → 연락 완료 → 진행 중 → 완료 (+ 취소) |
| **메모** | **새 칸 필요** | CL이 남기는 짧은 메모 |

> 지금 `sju_signups.status`는 active/cancelled(중복 방지용)라서 **CL 처리 상태와 메모 칸을 새로 추가**해야 함 (예: `handling_status`, `admin_note`, `handled_at`).

## 필요한 동작
1. 기본 정렬: 최신 신청이 위
2. 필터: 처리 상태, 결과코드, 트랙, 소식 받기 동의, 유입 경로(utm_source)
3. 처리 상태·메모를 목록에서 바로 바꾸기
4. 상단 숫자: 오늘 신청 / 처리 안 한 신청(신규) / 이번 주 신청
5. 내보내기(CSV): 행사 안내 문자 보낼 때 — **소식 받기 동의한 사람만** 내보내는 옵션
6. 삭제: 신청자가 삭제를 요청하면 지울 수 있어야 함 (동의 문구에 "삭제 요청: 인스타 DM"이라고 안내 중)

## 대응 규칙 (지원 수준 칸 요약용)
| 조건 | 화면에 보일 요약 |
|---|---|
| want_setup = true | "직접 세팅 희망" |
| level = 처음 / 잘 씀 | "입문 행사 같이 안내" / "심화 버전" |
| usage = 아무도 안 씀 / 몇 명만 씀 / 다 같이 씀 | "제작+온보딩" / "템플릿+가이드" / "고도화" |
| track = 운영진·멤버 이고 결과가 O1~O4 | "대표 연결 필요" (이 경로는 usage가 비어 있음) |
| 결과 P4 | "행사 안내 (행사 없으면 대기 명단)" |

## 꼭 지킬 것
- 동의 문구에 "보유 기간: 신청일로부터 1년 (이후 바로 파기)"라고 적혀 있음 → **1년 지난 신청을 자동으로 지우는 장치**(Supabase 예약 작업 등)가 어드민과 같이 있어야 함. 지금은 없음
- 화면은 세종이네 노션 톤(크림 배경·버건디 강조·Pretendard) 정도만 맞추면 충분. 폰에서도 목록 확인 가능하게
